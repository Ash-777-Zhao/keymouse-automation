# 鼠标宏 · 录制 / 回放 / 剧本

两种玩法：

- **录制**：录下屏幕上的鼠标动作（移动轨迹、点击、滚轮），按指定次数重复回放；
- **剧本**：在屏幕上点选坐标，一步步指定「在这个点做什么鼠标动作、之后输入什么文字」。

两者共用同一套回放引擎（重复次数、倍速、循环间隔）。

双击 `启动.bat` 运行，或者命令行执行：

```
python mouse_macro.py
```

双击后会先弹出一个黑色命令行窗口，程序界面紧跟着打开；关掉界面程序就退出，
命令行窗口是留着看报错用的。不想要这个黑窗口的话，把 `启动.bat` 里的
`python` 改成 `pythonw`（代价是出错时什么都看不到）。

**如果黑窗口一闪而过**，说明启动就失败了。这时在命令行里手动跑一遍看报错：

```
cd /d 这个文件夹的完整路径
python mouse_macro.py
```

> 关于 `启动.bat`：这个文件必须保持**纯 ASCII 内容 + CRLF 行尾**。
> cmd.exe 是按字节偏移来读批处理文件的，UTF-8 中文加上 LF 行尾会让它算错行边界，
> 把 `echo` 和下一行的内容粘在一起当命令执行，表现就是窗口一闪就没。
> 中文说明一律放这个 README 和程序界面里，不要写进 bat。

## 环境

- Windows
- Python 3.10 以上（当前用的是 3.12）
- 依赖只需要 `pynput`：

```
python -m pip install pynput
```

## 怎么用

1. 点「● 开始录制 F9」。会留 1.2 秒缓冲，让手指先离开鼠标。
2. 正常操作鼠标。界面上会实时显示已经记录了多少个动作。
3. 按 `F9` 停止录制（也可以按界面上的停止按钮）。
4. 录多了、录错了，在列表里选中后按 `Delete` 删掉，不用整个重录。
5. 在右侧设置里填好重复次数。
6. 按 `F10` 开始回放，`F11` 随时停止。

录好的宏可以「保存…」成 `.json` 文件，下次「加载…」回来。默认存在 `macros/` 目录里。

## 编辑录制好的宏

动作列表上方有三个操作：

| 操作 | 说明 |
|---|---|
| 删除选中 | 删掉选中的动作。列表支持 `Ctrl` 点选和 `Shift` 连选，也支持 `Delete` 键 |
| 从选中处回放 | 以选中的第一个动作作为起点跑到结尾。调试长宏时不用每次都从头看 |
| 全选 | 等价于 `Ctrl+A` |

**删除会收紧时间轴。** 每个动作都带着一段「距上一个动作的等待」，删掉一个动作时，
它前面那段等待也一并消失——这样剩下的动作回放起来，就像被删的那个从来没发生过。
否则删掉一个误点之后，回放时那个位置会莫名其妙停一下。

举个例子，录制结果的时间戳是 `0 / 500 / 520 / 900` 毫秒，删掉第 2 个动作后变成
`0 / 20 / 400`：第 2 个动作那 500ms 的等待被消掉了，后面整体前移。

不想改时间轴的话，删之前先「保存…」一份，或者靠右侧的「播放速度」整体调节奏。

## 热键

| 默认键 | 作用 |
|---|---|
| `F9` | 开始 / 停止录制 |
| `F10` | 开始回放 |
| `F11` | 停止当前操作 |
| `F8` | 取点：把当前鼠标位置加为剧本的一步 |

热键是全局的，窗口在后台也能用。如果热键被别的程序占用了，界面按钮一样能用。

**热键可以自己改**：右侧「热键」面板里点对应按钮，再按下想用的键即可（`Esc` 取消）。
想用 F1~F12 之外的单键也可以，但不建议——单字母键在任何地方打字都会触发动作。
改完会立刻生效，并存进 `settings.json`，下次打开还是你设的键。
和别的功能撞键会被拒绝并提示；点「恢复默认」可以退回 F9 / F10 / F11。

## 设置项

| 设置 | 说明 |
|---|---|
| 重复次数 | 整个宏播放多少轮 |
| 无限循环 | 勾上后忽略重复次数，一直播到按 F11 |
| 播放速度 | 1 倍 = 完全按录制时的手速；2 倍 = 快一倍。范围 0.25 ~ 8 |
| 循环间隔 | 每一轮之间的停顿，单位毫秒 |
| 还原移动轨迹 | 勾上则连鼠标划过的路径一起还原；取消则直接跳到点击位置，适合固定几点连点 |
| 用模拟按键方式输入 | 键盘输入改走模拟真实按键的路径，只在目标程序不认 Unicode 通道时才需要；会被输入法干扰 |
| 忽略本窗口内的操作 | 避免把点「开始录制 / 停止录制」按钮的动作也录进去。**默认关闭** |
| 忽略其他程序注入的输入 | 只记录真实硬件输入，滤掉别的宏工具或远程桌面产生的假输入。默认开启 |

两项过滤都会**静默吃掉动作**。所以如果发现录制「没反应」，先把这两个勾都取消掉试试。

## 编写剧本

界面顶部有两个页签，「录制」和「剧本」。剧本适合**不用录也能精确定位**的场景。

### 一步步来

1. 切到「剧本」页签。
2. 点「屏幕上取点添加」——整个屏幕会变暗、出现十字准星，移动鼠标时跟着显示实时坐标，
   点一下就把那个坐标取下来（`Esc` 或右键取消）。
3. 弹出的对话框里设这一点的**鼠标动作**、可选的**输入文字**、以及**执行后等待**多久。
4. 重复上面两步，把所有点加完。
5. 按 `F10` 回放。

想更快的可以用 `F8`：把鼠标移到目标位置，按一下 `F8`，直接按当前位置加一步
（默认左键单击、等 500 毫秒），之后再双击某一行改细节。

### 一个步骤包含什么

| 字段 | 说明 |
|---|---|
| 坐标 | 屏幕绝对像素，可以用「屏幕上取点…」按钮重取 |
| 鼠标动作 | 左键单击 / 右键单击 / 中键单击 / 双击 / 滚轮上 / 滚轮下 / 仅移动 |
| 输入文字 | 执行完鼠标动作之后输入这段内容，留空表示不输入。字母、数字、中文都可以 |
| 执行后等待 | 这一步做完等多少毫秒再做下一步，默认 500 |

列表上方还有「编辑」「删除」「↑」「↓」「清空」。`↑` `↓` 用来调顺序，
双击某一行等同于「编辑」。剧本可以「保存…」成 `.json`，下次「加载…」回来——
加载时会自动识别文件是剧本还是录制，并切到对应页签。

### 关于输入文字

默认走的是 `SendInput` 的 Unicode 通道，直接把「要输入这个字符」告诉系统，
不经过键盘布局，**也不经过输入法**。

这一点很关键：如果系统开着中文输入法，走「模拟按键」那条路的话，发出去的
`abc` 会被输入法当成拼音，打出「饿了咯」这种中文（这是实测踩到的坑）。

代价是 Unicode 通道只产生字符、不产生真实扫描码，**少数只读扫描码的程序
（部分游戏）可能收不到**。那种场景才需要勾上「用模拟按键方式输入」——
勾上之后就能被输入法干扰了，二选一。

## 录制「没反应」怎么查

录制时状态栏下面会实时显示一行采集统计，比如：

```
钩子收到 412 个事件  ·  已记录 96  ·  忽略注入 310  ·  轨迹合并 6  ·  最近 左键按下 @ 1285, 724
```

对着这行数字就能定位问题：

| 现象 | 说明 | 怎么办 |
|---|---|---|
| `钩子收到 0 个事件` | 系统钩子压根没抓到输入 | 最可能是目标程序以管理员身份运行，见下面「管理员权限」 |
| `忽略注入` 数字很大 | 输入是你自己或其他宏工具注入的，不是真实硬件 | 取消勾选「忽略其他程序注入的输入」 |
| `忽略本窗口` 数字很大 | 你的操作落在本工具窗口范围内，被过滤了 | 取消勾选「忽略本窗口内的操作」，或把窗口挪开 |
| 数字在涨但列表是空的 | 列表只在**停止录制之后**才填充 | 按一下停止热键 |

## 几个容易踩的坑

**管理员权限。** 如果目标程序是以管理员身份运行的，本工具也必须以管理员身份启动，
否则发送的按键会被系统拦掉，表现为「回放看起来在跑，但目标程序毫无反应」。

**坐标是绝对屏幕像素。** 宏文件里存的是绝对坐标，所以下面这些情况下回放会点偏：

- 换了分辨率，或者改了显示器的排列方式
- 目标窗口换了位置、或者窗口尺寸变了
- 多显示器时副屏被拔掉

这类场景建议取消勾选「还原移动轨迹」，改成录制相对固定的点位。

**多显示器和负坐标。** 如果副屏摆在主屏左边或上边，副屏上的坐标是负数，这是正常的，
工具已经支持。

**高 DPI 缩放。** 程序启动时会先声明 DPI 感知再创建窗口，保证录到的坐标和实际鼠标位置
一一对应。如果屏幕缩放是 100% 以外（比如 150%），这一点尤其重要。

## 文件说明

| 文件 | 作用 |
|---|---|
| `mouse_macro.py` | 主程序，tkinter 界面 |
| `recorder.py` | 鼠标采集，全局钩子 + 移动点抽稀 |
| `player.py` | 回放，按时间轴在后台线程重放 |
| `macro_model.py` | 动作数据结构与 `.json` 存取 |
| `script_model.py` | 剧本步骤的数据结构，以及展开成动作序列 |
| `screen_picker.py` | 全屏取点覆盖层 |
| `step_dialog.py` | 步骤编辑对话框 |
| `keyinput.py` | 键盘输入（Unicode 通道 + 模拟按键两条路） |
| `selftest.py` | 自检脚本，回放部分用假控制器，不会真的动鼠标 |
| `settings.json` | 热键配置，改过键之后才会生成 |

跑自检：

```
python selftest.py
```

## 实现上值得一提的两点

**移动点抽稀。** 鼠标钩子的回调频率可以到每秒几百次，全记下来会得到一个几万条的宏文件。
采集时按「位移小于 3 像素 **且** 间隔小于 20 毫秒就丢弃」的规则过滤，
长按拖动 10 秒大约也就几百个点，回放观感和原速基本一致。

**点击前补定位。** 抽稀之后，最后一个移动采样点和实际点击位置可能差几个像素。
所以每次点击 / 滚轮之前，如果指针不在该坐标，会补一个精确的移动动作，
保证落点分毫不差。
